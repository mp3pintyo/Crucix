# v2.14.0 — Pivot-linkek: „Keresés máshol” a rekordböngészőben / Pivot links: "Look up elsewhere" in the record inspector

## Magyar

Forrás: az [awesome-osint-arsenal](https://github.com/rawfilejson/awesome-osint-arsenal) eszközkatalógus elemzése. A repó nem adatforrás-gyűjtemény (753 eszköz, 26 kategória), ezért csak a Crucix profiljába illő részét vesszük át: az ellenőrzött, kulcs nélküli keresőoldalakat, entitástípus szerint.

### 1. Pivot-linkek a rekordböngésző részletnézetében

- **Mit lát a felhasználó:** egy rekord részletei alatt új „Keresés máshol” blokk jelenik meg, ha a rekordban felismerhető entitás van. Minden entitás mellett néhány, új lapon megnyíló keresőoldal-hivatkozás áll.
- **Felismert entitások:** CVE-azonosító, publikus IPv4-cím, Ethereum- és Bitcoin-cím a címből, az összefoglalóból és a tények értékeiből; tartomány (domain) és LEI csak akkor, ha a tény címkéje is azt jelöli (egy cím közepén álló szót sosem tekintünk tartománynak). Magán-, loopback-, link-local-, CGNAT- és fenntartott IP-tartományok nem kapnak linket. Rekordonként legfeljebb 6 entitás.
- **Linkek:** CVE → NVD, CVE.org; IP → VirusTotal, AbuseIPDB, GreyNoise, Shodan; domain → VirusTotal, urlscan, crt.sh; Ethereum → Etherscan, Blockchair; Bitcoin → Blockchair, WalletExplorer; LEI → GLEIF.
- **Adatvédelem és biztonság:** a Crucix semmit nem kér le: a link csak kattintásra nyílik meg (`rel="noopener noreferrer"`), így semmilyen azonosító nem távozik kattintás előtt, és nem kell hozzá API-kulcs vagy kvóta. Az érték százalékkódolva kerül a sablonba, a megjelenítés a meglévő `esc`/`safeUrl` útvonalon megy.
- **Opcionális modul:** új [pivots.js](../../dashboard/public/pivots.js) (`window.CrucixPivots`); a rekordböngésző nélküle is a régi módon működik. A fájl bekerült az oldalba és a PWA-shell listájába, az új felirat (`inspector.pivots`) magyarul, angolul és franciául is megvan.
- **Ellenőrzés:** a sablonok élő oldalakra mutatnak (NVD 301, CVE.org, VirusTotal, Shodan, urlscan, Etherscan, WalletExplorer, GLEIF 200; az AbuseIPDB, GreyNoise és Blockchair 403/401-et ad a curlnek, azaz robotvédelem, nem hiányzó oldal).

**Ellenőrzés:** 5 új teszt ([test/pivots.test.mjs](../../test/pivots.test.mjs)): entitásfelismerés (magán-IP-k és hasonló szövegek kizárása), a címke-feltételes domain és LEI, a százalékkódolás és a 6-os korlát, a megjelenítés escape-elése és a modul nélküli működés, az oldal- és service worker-bekötés. Célzott futás: 89 teszt, 0 hibás (pivots, rekordböngésző, nyelvi fájlok, böngészőkompatibilitás, PWA, óra és paletta). `npm run check` rendben. A „tartsd szűken” szabály szerint a teljes csomagot nem futtattam; a CI teszi.

**Átállás:** nincs konfiguráció- vagy adatváltozás; a böngészőlapot frissítsd. A PWA shell gyorsítótára változatlanul `crucix-shell-v2.13.0` (az online oldal hálózat-első).

## English

Source: an analysis of the [awesome-osint-arsenal](https://github.com/rawfilejson/awesome-osint-arsenal) tool catalogue. The repo is not a data-source collection (753 tools, 26 categories), so only the part that fits Crucix is taken over: verified, keyless lookup pages, grouped by entity type.

### 1. Pivot links in the record inspector's detail view

- **What the user sees:** below a record's details a new "Look up elsewhere" block appears when the record holds a recognisable entity. Each entity comes with a few lookup-page links that open in a new tab.
- **Recognised entities:** CVE id, public IPv4 address, Ethereum and Bitcoin address from the title, summary and fact values; a domain or a LEI only when the fact label says so (a word inside a title is never taken for a domain). Private, loopback, link-local, CGNAT and reserved IP ranges get no link. At most 6 entities per record.
- **Links:** CVE → NVD, CVE.org; IP → VirusTotal, AbuseIPDB, GreyNoise, Shodan; domain → VirusTotal, urlscan, crt.sh; Ethereum → Etherscan, Blockchair; Bitcoin → Blockchair, WalletExplorer; LEI → GLEIF.
- **Privacy and security:** Crucix fetches nothing: a link opens only on click (`rel="noopener noreferrer"`), so no identifier leaves before then, and no API key or quota is needed. The value is percent-encoded into the template and rendered through the existing `esc`/`safeUrl` path.
- **Optional module:** new [pivots.js](../../dashboard/public/pivots.js) (`window.CrucixPivots`); the inspector works as before without it. The file is wired into the page and the PWA shell list, and the new label (`inspector.pivots`) exists in English, Hungarian and French.
- **Check:** the templates point at live pages (NVD 301; CVE.org, VirusTotal, Shodan, urlscan, Etherscan, WalletExplorer and GLEIF 200; AbuseIPDB, GreyNoise and Blockchair answer curl with 403/401, i.e. bot protection, not a missing page).

**Validation:** 5 new tests ([test/pivots.test.mjs](../../test/pivots.test.mjs)): entity detection (private IPs and look-alike text excluded), label-gated domain and LEI, percent-encoding and the cap of 6, escaping in the render and working without the module, the page and service-worker wiring. Targeted run: 89 tests, 0 failed (pivots, record inspector, locales, browser compatibility, PWA, clock and palette). `npm run check` passes. Following the "keep it lean" rule I did not run the full suite; CI does.

**Upgrade:** no configuration or data change; reload the browser tab. The PWA shell cache stays at `crucix-shell-v2.13.0` (the online page is network-first).
