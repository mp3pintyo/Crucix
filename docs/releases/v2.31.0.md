# v2.31.0 — Beágyazás és API-dokumentáció: CORS és iframe engedélyezés, állapot-widget, a README szétbontása / Embedding and API docs: CORS and iframe opt-ins, a status widget, the README split into pages

## Magyar

Egy felhasználó azt kérdezte: lesz-e API, van-e beágyazási lehetőség? **API eddig is volt** (a felület is ezt használja), de nem volt dokumentálva, idegen weboldal nem tudta olvasni a böngészőből, és a szerver minden oldalt letiltott a keretezéstől. Ez a kiadás mindkettőt bekapcsolhatóvá teszi, dokumentálja, és szétbontja a túl hosszú README-t.

### Új: CORS (`CORS_ORIGINS`)

- Alapból kikapcsolt. `CORS_ORIGINS=https://pelda.hu,https://masik.org` (vagy `*`) esetén a felsorolt eredetű oldalak a böngészőből **olvashatják** a `GET /api/…` útvonalakat.
- Csak `GET`/`HEAD` és a `GET` előzetes (preflight) kérése kap `Access-Control-*` fejlécet; **a `POST`/`PUT`/`DELETE` soha** (idegen oldal nem módosíthat riasztást, a v2.10 same-origin őr változatlan). Hitelesítő adatos mód nincs engedve.
- Jelszóval védett szerveren a preflight a Basic auth előtt kap választ (a böngésző nem küld hozzá adatot), az adat továbbra is hitelesítést kér; az oldal maga küldi az `Authorization` fejlécet.
- `CORS_ORIGINS=*` hitelesítés nélkül figyelmeztetést ír indításkor.

### Új: beágyazás (`EMBED_ORIGINS`) és az állapot-widget

- `EMBED_ORIGINS=https://pelda.hu` esetén a felsorolt oldalak `<iframe>`-ben megjeleníthetik a vezérlőpultot (`/`) és az új **`/embed.html`** widgetet (`frame-ancestors`); minden más oldal marad `X-Frame-Options: DENY`. Csak pontos eredet adható meg (`*` nem).
- **`/embed.html`**: kis kártya a fenyegetettségi szinttel (1–5), a legfontosabb riasztásokkal és a legmagasabb országkockázatokkal. Paraméterek: `lang` (en/hu), `theme` (dark/light), `alerts`, `countries`, `refresh`. Nem tölt be külső betűtípust vagy szkriptet, a szerver szövegeit csak szövegként írja ki. Fejetlen Chromiummal ellenőrizve: megjelenik, a másik eredetű oldal be tudja keretezni, a nem engedélyezett oldalt (`/jarvis.html`) nem, egy `<img onerror>` című riasztás nem fut le. (Az első ellenőrzésen kiderült egy hiba: hiányzó `alerts`/`countries` paraméternél 0 sor jelent meg; javítva a kiadás előtt.)

### Új dokumentáció

## English

A user asked: will there be an API, and can it be embedded? **The API already existed** (the dashboard itself uses it) but it was undocumented, a foreign website could not read it from a browser, and the server forbade framing every page. This release makes both possible as opt-ins, documents them, and splits the over-long README.

### New: CORS (`CORS_ORIGINS`)

- Off by default. With `CORS_ORIGINS=https://example.com,https://other.org` (or `*`) pages from the listed origins can **read** the `GET /api/…` routes from a browser.
- Only `GET`/`HEAD` and the preflight of a `GET` get `Access-Control-*` headers; **never `POST`/`PUT`/`DELETE`** (a foreign page cannot change alerts, the v2.10 same-origin guard is untouched). Credentials mode is not granted.
- On a password-protected server the preflight is answered before the Basic auth (the browser sends no credentials with it); the data still needs them, and the page sends the `Authorization` header itself.
- `CORS_ORIGINS=*` without authentication prints a warning at start.

### New: embedding (`EMBED_ORIGINS`) and the status widget

- With `EMBED_ORIGINS=https://example.com` the listed sites may show the dashboard (`/`) and the new **`/embed.html`** widget in an `<iframe>` (`frame-ancestors`); every other page stays `X-Frame-Options: DENY`. Exact origins only (`*` is not accepted).
- **`/embed.html`**: a small card with the threat level (1–5), the top alerts and the highest country risks. Parameters: `lang` (en/hu), `theme` (dark/light), `alerts`, `countries`, `refresh`. It loads no external font or script and writes server text only as text. Checked in headless Chromium: it renders, a page on the other origin can frame it and cannot frame a page that was not allowed (`/jarvis.html`), and an alert titled `<img onerror>` does not run. (The first check found a bug: with no `alerts`/`countries` parameter it showed 0 rows; fixed before the release.)

### New documentation

- [docs/API.md](../API.md): every readable route with parameters, error format, authentication, CORS and recipes (curl, jq, EventSource). It replaces the README's old, incomplete endpoint table (`/api/history`, `/api/export` and `/api/events/:id` were missing from it).
- [docs/EMBEDDING.md](../EMBEDDING.md): the widget, the full dashboard, your own widget from the API, what exactly the two variables allow, password-protected servers.

### The README split

GitHub READMEs have no tabs, so the 785-line README became **214 lines**: the short pitch, quick start, access and privacy stay, and a **Documentation** table leads to the detail: [Features by release](../FEATURES.md), [Configuration](../CONFIGURATION.md) (keys, bots, LLM, npm), [Data sources](../DATA-SOURCES.md), [HTTP API](../API.md), [Embedding](../EMBEDDING.md), [Architecture](../ARCHITECTURE.md), [Troubleshooting](../TROUBLESHOOTING.md). The text moved verbatim (heading levels and relative links adjusted); a check run over the internal links and anchors of the README and `docs/*.md` found 0 broken.

### Validation

- New tests: 5 ([test/web-access.test.mjs](../../test/web-access.test.mjs): the default is unchanged; CORS read-only and only for a listed origin; preflight before Basic auth, data still authenticated; framing only for `/` and `/embed.html`, only for listed origins; the widget reads only the two public routes and never uses `innerHTML`).
- Run: those 5 and the HTTP-security, dashboard-security, alert-routes, PWA, environment and API-error tests, 59 tests in all, 0 failed (Node 24); the 33 tests of the main security files also pass on Node 22; `npm run check` passes. The full suite did not run (`jarvis.html` is unchanged).
- Known limits: in the iframe of a password-protected server many browsers block the Basic-auth prompt on a foreign site; the [guide](../EMBEDDING.md#with-a-password-auth_user--auth_password) gives two ways around it. The API has no version number and no OpenAPI description.
