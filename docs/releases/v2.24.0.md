# v2.24.0 — Figyelőlista: a referenciaprojektek egy fájlban, és egy parancs, ami megmutatja a változásaikat / Watchlist: the reference projects in one file, and a command that shows what changed in them

## Magyar

- **A tároló:** [docs/watchlist.json](../watchlist.json): azok a projektek, amelyekből a Crucix tanul. Projektenként: azonosító, név, cím, tároló, licenc, **miért figyeljük**, **mit vettünk át belőle** (kiadásszámmal), **mi maradt ki vagy nyitott**, és a **utolsó átnézés** (a tároló akkori feje és dátuma). Induláskor három projekt van benne: [awesome-osint-arsenal](https://github.com/rawfilejson/awesome-osint-arsenal) (v2.14.0–v2.17.0 készült belőle), [World Monitor](https://github.com/koala73/worldmonitor) (v2.18.0–v2.23.0) és a [God's Eye View](https://github.com/bilawalsidhu/gods-eye-view) (még nincs elemezve; licence nincs megadva, ezért egyelőre csak ötletet és nyilvános adatforrást érdemes átvenni, kódot nem).
- **A parancs:** `node scripts/watchlist.mjs` minden projektre kiírja, hány új commit és milyen kiadás jelent meg az utolsó átnézés óta, a legújabb 12 commit sorával. `node scripts/watchlist.mjs <azonosító>` egy projektet mutat 40 sorral; `--list` kérés nélkül csak a tartalmat mutatja; `--mark <azonosító> [megjegyzés]` rögzíti, hogy a projekt mai fejét átnéztük (frissíti a fájlt). Új projekt felvételéhez elég egy új bejegyzést írni a fájlba. Klónozás nincs, projektenként 2–3 GitHub API-kérés; `GITHUB_TOKEN` környezeti változóval a névtelen óránkénti 60-as korlát megemelhető.
- **Első futás (2026-10-08):** awesome-osint-arsenal: nincs új commit; World Monitor: 19 új commit az átnézés óta (köztük UNHCR határon átnyúló mozgás, IOM DTM belső lakóhelyelhagyás, kínai MIIT-tartalék); God's Eye View: még nem elemzett, a feje 2026-10-07, négy kiadással (v0.1.0–v0.2.1).
- **Használat később:** elég azt mondani, hogy „nézd meg a figyelőlistát”: a fájlt vagy a parancsot futtatom, és a változásokból javaslatot teszek. Ellenőrzés: 2 új teszt ([test/watchlist.test.mjs](../../test/watchlist.test.mjs): a fájl érvényessége és a három induló projekt; az újdonságok összegzése, hibakezelés és a „még nem elemzett” eset); `npm run check` rendben.

## English

- **The store:** [docs/watchlist.json](../watchlist.json): the projects Crucix learns from. Per project: id, name, URL, repository, licence, **why we watch it**, **what we took from it** (with release numbers), **what was left out or is open**, and the **last review** (the repository's head and the date then). It starts with three projects: [awesome-osint-arsenal](https://github.com/rawfilejson/awesome-osint-arsenal) (v2.14.0–v2.17.0 came from it), [World Monitor](https://github.com/koala73/worldmonitor) (v2.18.0–v2.23.0) and [God's Eye View](https://github.com/bilawalsidhu/gods-eye-view) (not analysed yet; no licence is stated, so for now only ideas and public data sources are worth taking, not code).
- **The command:** `node scripts/watchlist.mjs` prints, for every project, how many new commits and which releases appeared since the last review, with the newest 12 commit lines. `node scripts/watchlist.mjs <id>` shows one project with 40 lines; `--list` shows the content without any request; `--mark <id> [note]` records that the project's current head was reviewed today (it updates the file). To add a project, write one more entry in the file. Nothing is cloned, 2–3 GitHub API requests per project; the `GITHUB_TOKEN` environment variable lifts the anonymous limit of 60 an hour.
- **First run (2026-10-08):** awesome-osint-arsenal: no new commits; World Monitor: 19 new commits since the review (among them UNHCR cross-border movements, IOM DTM internal displacement, a China MIIT fallback); God's Eye View: not analysed yet, its head is from 2026-10-07, with four releases (v0.1.0–v0.2.1).
- **Using it later:** just say "check the watchlist": I run the file or the command and propose what to take from the changes. Validation: 2 new tests ([test/watchlist.test.mjs](../../test/watchlist.test.mjs): the file's validity and the three starting projects; the summary of changes, error handling and the "not analysed" case); `npm run check` passes.
